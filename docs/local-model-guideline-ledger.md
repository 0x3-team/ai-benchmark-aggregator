# Local Model Guideline Ledger

> Scope: local orchestration guidance for this repository. This is **not** part of the benchmark-result ledger and must never be presented as an official benchmark claim, exported to the product UI, or used to overwrite source-backed benchmark data.

## Purpose and ownership

Codex is the primary orchestrator: it decomposes work, selects narrow model lanes, reviews every result, integrates accepted changes, runs project checks, and records what was learned. A model's self-report, benchmark score, or successful command is evidence—not proof that a change is correct.

This document contains a derived current view plus an append-only task history. When evidence changes, add a dated observation and update the current-view fields with a link to that observation; do not erase a prior failure.

## Non-negotiable operating rules

- Do not modify user work, commit, push, deploy, change credentials, or run package/tool updates without the authority required for that action.
- Preserve the repository's ledger trust boundary: the Python result ledger stores external source claims only; this document stores internal routing observations only.
- Use the highest reasoning setting exposed by the selected harness. If the harness has no observable non-interactive effort control, record it as `requested but unverified` rather than claiming it was applied.
- Use existing terminal sessions only when they are safely controllable. Do not inject commands into an unknown PTY. Use a supervised dedicated PTY otherwise.
- Parallelize only independent, non-overlapping slices. A single parent owns integration and must accept, adapt, reject, or mark each worker result unverified.
- A model cannot self-verify: acceptance requires parent review plus the relevant tests, build, rendered UI check, CLI evidence, or other target-perspective proof.
- No automatic model, CLI, skill, plugin, or package updates. Inventory/update status is evidence only; obtain explicit approval before an update.

## Evidence model

### Evidence classes and weights

| Class | Examples | Initial weight |
|---|---|---:|
| Parent-verified project result | Scoped change reviewed by Codex; required checks and target evidence pass | 1.00 |
| Bounded local calibration | Model response completed, scope and actual output inspected | 0.55 |
| Runtime/access observation | Model list, auth/credit response, CLI option, or harness error | 0.45 |
| Primary-source documentation | Official model or provider documentation | 0.35 |
| Vendor benchmark or self-description | Model/provider leaderboard or marketing claim | 0.15 |

`routing_confidence` is a bounded judgement, not a calculated success rate. It must fall when an execution is blocked, times out, needs significant repair, or fails independent validation. It rises only after repeated parent-verified results in the same task category.

### Freshness and decay

- Model identifiers and documented interface facts: re-check after 90 days or a version/harness change.
- Access, credits, rate limits, latency, and cost: re-check after 7 days or every failure.
- Local performance and routing observations: halve their influence after 30 days without a comparable task.
- Any model-version, provider, or harness change starts a new profile revision. Historic observations remain visible but do not silently transfer to the new revision.

### Mandatory delegate telemetry contract

Every non-trivial delegated task must include this request in the harness prompt:

```text
Before your final answer, provide a USAGE_REPORT with the actual provider/model,
requested and observed reasoning effort, input/output/reasoning/cache token counts,
total tokens, tool-call count, elapsed time, and cost. If your interface cannot see a
field, write NOT_EMITTED; never estimate or invent it.
```

The parent must also collect the harness-native metering and reconcile it with the model's report. Native telemetry is authoritative; a model self-report is a helpful receipt, not accounting evidence.

| Harness | Parent collection rule |
| --- | --- |
| Cline | Run with `--json`; record `run_result.model`, `usage`, and `aggregateUsage`. Require the prompt-level `USAGE_REPORT` too. |
| Kilo | Run with `--format json`; record the final session/step token objects and cost, preserving cache counts and avoiding double-counting multi-step totals. Require the prompt-level `USAGE_REPORT` too. |
| Command Code, OpenCode, Antigravity | Ask for the same `USAGE_REPORT`, then capture the CLI/session/IDE telemetry when exposed. If no native telemetry exists, record `NOT_EMITTED` rather than a guessed total. |

No delegated result is considered fully closed until the parent records either reconciled usage or an explicit `NOT_EMITTED` reason in the task receipt and this ledger's performance history.

## Initial routing strategy

| Task fingerprint | First choice | Required settings / guardrails | Fallback |
|---|---|---|---|
| UI implementation, information architecture, visual design critique | Cline + GLM-5.2 | `--thinking xhigh`; explicit scope and hard timeout; use an interactive approval session, or `--auto-approve true` only inside an OS-level sandbox/read-only snapshot with no sensitive credentials | Codex parent or an independently validated Antigravity lane |
| Architecture, text-heavy debugging, root-cause reasoning, difficult review | Command Code + DeepSeek V4 Pro | `--model deepseek/deepseek-v4-pro`; use a controlled interactive PTY to set and capture `/effort max` before project work—print mode is advisory only because effort is not observable | Codex parent; premium Antigravity/Opus only after local access is verified |
| Repetitive, bounded utility work, fixtures, formatting, straightforward scaffolding | Kilo + Tencent Hy3 free route | `--model kilo/tencent/hy3:free --variant high --thinking`; use interactive approval, or `--dangerously-skip-permissions` only inside an OS-level sandbox/read-only snapshot; narrow files and mandatory parent review | Codex parent or Command Code when reasoning/reliability risk rises |
| Creative alternatives, novel solution exploration, long-context/agent design ideas | OpenCode + Muse Spark 1.1 | `--model meta/muse-spark-1.1 --variant xhigh --thinking`; cap context/cost and require a separate technical review | Codex parent or DeepSeek architecture pass |
| High-quality validation, multimodal/browser iteration, difficult edge cases | Antigravity + Gemini 3.5 Flash (High) | Use only from a connected IDE/agent bridge with the actual model and `High` setting visible; do not infer an Opus route | Codex-owned validation until the bridge is available |
| Premium adjudication / security-sensitive final review | Claude Opus 4.6 in Antigravity | **Not currently eligible:** canonical model exists in documentation, but no local Antigravity selector was verified | Codex parent plus an independent available reviewer |

Routing is not a quota system. When task fit and evidence are equivalent, distribute low-risk independent work across healthy lanes; otherwise select the best justified specialist. Free Hy3 capacity is valuable for bounded work, but it is not assumed unlimited: the paid Hy3 route returned a zero-credit error and the free route may still be rate limited.

### Required routing decision receipt

Before each non-trivial request, the parent records:

```text
Task ID:
Objective and acceptance criteria:
Task fingerprint: surface, ambiguity, risk, visual/tool needs, expected scope, budget/time cap
Dependencies and parallel-safe slices:
Selected lane(s), requested model/effort, and fallback:
Why this route is supported by current evidence:
Allowed files/areas and forbidden actions:
Telemetry contract and parent collection method:
Parent verification plan:
```

For write-scoped work, each child receives one narrow duty, non-overlapping files, explicit acceptance criteria, test commands, and a `DoneClaim`. The parent records the decision to accept, adapt, reject, or re-run it.

## Lessons learned — append-only

1. **2026-07-13 — Treat availability as a first-class routing dimension.** Kilo's catalog and a free model route did not establish paid-route access; model menu entries are not entitlement evidence.
2. **2026-07-13 — Maximum reasoning requires a time budget.** Cline's `xhigh` pass produced no result before parent interruption; keep xhigh as the requested setting but bound the task and stop a nonproductive run.
3. **2026-07-13 — Measure harness overhead, not just answer quality.** Muse delivered useful ideas but attached a large input-token footprint to a small prompt. It is not an efficiency lane until a larger sample says otherwise.
4. **2026-07-13 — Calibrations must be task-shaped.** DeepSeek, Hy3, and Muse each contributed useful evidence in their proposed lanes, but one read-only response cannot prove autonomous implementation quality.
5. **2026-07-13 — A configured integration is not a callable integration.** Antigravity must pass a connected-bridge smoke test before it enters the active worker pool.
6. **2026-07-13 — Headless approval policy can dominate model capability.** Cline/GLM and Kilo/Hy3 were both unsuitable for this source-audit pass because their harnesses denied read actions. Do not spend an audit slot on either unless a safe interactive approval path or pre-collected evidence bundle is available.
7. **2026-07-13 — Max-reasoning architecture review needs an explicit fan-out budget.** DeepSeek's independently useful reasoning came with four large explorer passes and an outside-workspace plan artifact. For constrained audits, ask for a fixed number of files/findings, prohibit project writes, and stop after the evidence receipt.
8. **2026-07-13 — Independent validation remains the integration bottleneck.** External-agent findings became valuable only after source/line review and bounded reproductions; claims without direct evidence were omitted from the final audit.
9. **2026-07-13 — Route audit work by evidence access first.** The current best pattern is a Codex-owned integration pass plus narrow local validators, reserving external models for bounded advisory analysis rather than treating model variety as a quality signal.
10. **2026-07-13 — The Cline block was configuration, not model availability.** GLM-5.2 completed both a no-tool smoke and an auto-approved disposable-file read. The exact restriction is that `--auto-approve false` cannot approve tools in a noninteractive session.
11. **2026-07-13 — Kilo's headless block is also a permission-mode issue.** HY3 Free completed a no-tool smoke and a `--dangerously-skip-permissions` disposable-file read; its default headless read ended `content-filter` before tool execution. Prefer interactive approval; never normalize the dangerous flag in a developer checkout.
12. **2026-07-13 — Ask for a telemetry receipt, but trust harness telemetry.** Both models followed the `USAGE_REPORT` contract and returned `NOT_EMITTED` for fields outside their context. The Cline and Kilo JSON streams supplied the authoritative token/cost totals; future orchestration must preserve both records and reconcile them.
13. **2026-07-13 — Model routing belongs at task granularity, not phase labels.** The remediation plan maps every task to an execution lead, a distinct review/validation subagent, a safe harness mode, and a telemetry collector. This keeps DeepSeek on high-ambiguity truth/migration work, Cline on UI, Kilo on bounded mechanics, and unavailable/expensive lanes conditional rather than decorative.
14. **2026-07-13 — A no-tool UI review can still improve accessibility, but it needs an evidence check.** GLM-5.2 correctly highlighted that native disabled controls hide their explanatory relationship from keyboard users; the parent verified and adapted it. Its 78.7-second / 11,825 visible-token footprint is appropriate for a high-risk UI boundary, not a routine lint pass.
15. **2026-07-13 — HY3 is useful for adversarial containment prompts, not authoritative architecture.** The 35,166-token no-tool review supplied one good defense-in-depth idea, but also alleged bypasses disproved by the real code. Keep HY3 as a bounded reviewer whose findings must be line-checked before implementation.
16. **2026-07-13 — Temporary config governance is a containment switch, not durable source approval.** Keeping all current sources ineligible and rechecking policy on every runner invocation makes the Phase-0 boundary fail closed. Source revisions and append-only approvals remain mandatory future work.
17. **2026-07-13 — A visible max-effort mode is not a completion receipt.** DeepSeek's supervised plan session established the requested mode but emitted no answer or usage before the cap. Keep an independent local design lane and stop instead of stretching an unproductive agent window.
18. **2026-07-13 — HY3 adds value as a short adversarial pass after a concrete design exists.** Its 31,048-token migration review produced three testable gaps, all parent-verified and incorporated; it is still too high-overhead to use as a first-pass architecture authority.
19. **2026-07-13 — Migration tooling itself needs a fail-closed target selector.** A rehearsal URL that falls through to a configured default is a data-integrity incident. Require explicit URLs, inspect read-only first, stage copies, and record any logical restoration transparently.
20. **2026-07-13 — File attachment is not a no-tool substitute in Kilo.** An attached-file headless review can enter snapshot setup and end without a completion receipt or telemetry. For advisory High-reasoning tasks, send a concise design summary in the prompt and reserve file access for interactive approval or a sandboxed run.
21. **2026-07-13 — HY3 fixture critique is useful after the lifecycle is concrete.** Its 33,637-token review added four meaningful probes, but it also restated a state transition already covered by the implementation. Route it to bounded adversarial test design, then map each finding to actual state fields and tests before changing code.
22. **2026-07-13 — A no-tool Kilo review can still hit the content filter based on prompt shape.** Preserve the failed native receipt, retry only once with compact plain-language invariants, and do not compensate by granting tools or permissions in the main checkout.
23. **2026-07-13 — A capped DeepSeek print run is not a reliable substitute for a supervised max-effort review.** It can reach the watchdog without answer or telemetry. For time-critical integrity work, retain a parent-owned adversary/test lane and use DeepSeek only when an interactive effort acknowledgement and output budget are observable.
24. **2026-07-13 — Read-only prompting does not guarantee a clean harness workspace.** Command Code generated a generic taste template during a no-tool timeout. Inspect the working tree after every external harness call and run such reviews in an isolated workspace whenever possible.
25. **2026-07-13 — A dry-run is only honest when it avoids initialization as well as evidence writes.** Read-only preflight must happen before opening a normal ORM session, and the absent-database behavior needs its own test.
26. **2026-07-13 — A savepoint gives correct evidence rollback only when aggregation happens after release.** Keep source counters local until success and append the failed source's run-level outcome after the savepoint rolls back; immutable content-addressed orphan bytes require a separately audited GC policy rather than opportunistic deletion.
27. **2026-07-13 — A compact Kilo High advisory can find one good lifecycle edge case, but it remains a costly reviewer lane.** The LDR-004 pass added a valuable orphan-retry assertion at 32,820 tokens; keep it post-implementation and require parent line/test verification.
28. **2026-07-13 — Database containment needs a second line even when the runner is fail-closed.** The LDR-005 review correctly exposed that a foreign-key-style decision reference does not prove current certification. Require the database guard to reject stale snapshots, quarantined decisions, and multiple effective leaves; use the expensive Kilo advisory only after a concrete contract exists and verify every proposed gap locally.
29. **2026-07-13 — Retiring a source route is a provenance transition, never evidence cleanup.** A source revision can become inactive and its adapter can fail closed while pre-retirement raw claims and snapshots remain queryable; report or publication filtering belongs to LDR-09 rather than mutation. Kilo supplied useful bounded transition probes, and isolated supervised DeepSeek supplied the missing query-retention test, but only Kilo emitted task-level token telemetry.
30. **2026-07-13 — Offline parser mechanics are safe only under an explicit non-certifying contract.** A retired adapter may parse supplied fixture bytes for tests only when canonical retired mode emits nothing, candidates are unreviewed, validation fails, and an independently hypothetical active route is still policy-quarantined. Map summary-only reviewer concerns to the actual adapter code before expanding scope; Kilo supplied one useful probe, while DeepSeek accepted the clarified boundary.
31. **2026-07-13 — Retired network paths benefit from paired behavioral and static containment probes.** A fail-fast fetch test can guard lazy config/HTTP imports, while a narrow assertion that the known fallback host is absent prevents accidental reintroduction. Treat an advisory finding as already satisfied when its exact candidate and validation assertions are present; do not create duplicate tests merely because a summary omitted them.
32. **2026-07-13 — A test-only admission bypass needs a two-sided proof.** It is not enough to document monkeypatches or assert a policy classification: create an explicit disposable successor for fixture mechanics and independently prove the unpatched runner rejects that same active successor before adapter dispatch or any evidence write.
33. **2026-07-13 — Retired derived analytics can remain useful without being claims.** When the approved plan explicitly retains an offline aggregate for fixture analytics, preserve it only behind a canonical retired route with zero-confidence/unreviewed/failing-validation candidates and policy quarantine. Do not delete that permitted test mechanics solely because a summary-only reviewer assumes every calculation must be removed.
34. **2026-07-13 — Treat a review finding as a test-location hypothesis.** Kilo correctly wanted a direct-parser no-write proof for LiveCodeBench, but its claim that the marker assertions were absent was contradicted by the exact fixture test. Trace each proposed invariant to code, retain already-proven clauses, and add only the residual assertion.
35. **2026-07-13 — Legacy classification is a projection decision, not a rewrite.** A retired adapter can quarantine all future candidates while old raw claims remain unchanged and queryable. Record the source transition now; let LDR-09 build the inventory, quarantine/report, and publication omission without mutating the evidence record.
36. **2026-07-13 — Identity correction and validation promotion are distinct evidence.** A manual model mapping must append a review decision and leave the captured claim, validation rows, and capture status unchanged. Freeze the captured projection, require one effective decision chain, and make public readers label captured versus effective identity so an append-only correction cannot silently disappear.
37. **2026-07-13 — Deterministic candidate data and publication are separate gates.** A source-backed, reviewed, hypothetically approved fixture can prove unique-cell/provenance semantics without enabling an export path or Official UI. Keep the projection pure and timestamp-free for reproducibility; make conflicts all-or-nothing with a diagnostic report; preserve rejected/legacy evidence as an explicit exclusion for LDR-09 instead of treating old mutable status as approval.
38. **2026-07-13 — A SQLite “read” command must preflight before opening the ORM.** Opening a missing SQLite URL with a normal session can create an empty database even when the command only intends to query. For diagnostic/report commands, use a read-only inspection gate first and test the absent-file path explicitly.
39. **2026-07-13 — Reconciliation is not conflict resolution.** One pure eligibility analysis can serve a strict candidate projection and a complete diagnostic report: the projection still refuses all partial output, while the report inventories every eligible conflicting claim as `conflicted` with a stable explanation. Never turn a report-only disposition into a status update or a winner-selection rule.
40. **2026-07-13 — A containment artifact is not a publication artifact.** A fixed-path, no-output verifier can prove a tracked unavailable baseline without creating a route that repackages a candidate or report as Official data. Put semantic digest/schema/provenance checks in both ordinary and clean-archive CI, and keep Node-native tests outside Vitest discovery.
41. **2026-07-13 — Test the state transition in one committed React tree.** Separate server-rendered provider roots cannot expose a stale module-global handoff. For a provider migration, pin the DOM test environment directly, then use `StrictMode`, `createRoot`, `act`, and a commit probe to assert models, benchmarks, values, and provenance together in both transition directions.
42. **2026-07-13 — A file-attached or print-mode no-tool advisory can hang before model usage begins.** Stop the task at its watchdog, retain the zero/`NOT_EMITTED` receipt, and never let an unavailable reviewer hold the acceptance gate. Parent-owned target tests and a file-grounded internal review remain the fallback.
43. **2026-07-13 — Cleanup must name only the temporary resource it owns.** An over-broad `/tmp/tmp.*` cleanup attempt after stopping a hung advisory was inappropriate; two protected directories were refused and no workspace files were affected. Use each exact `mktemp` path and its scoped trap, never a shared-directory glob.
44. **2026-07-13 — A self-digest establishes byte integrity, not publication authority.** A future frontend artifact needs both Web Crypto verification and an independently controlled pin for artifact identity, approval decision, policy, and digest; neither an artifact's `published` label nor a matching hash may enable the UI alone.
45. **2026-07-13 — Keep a future parser dormant behind the current loader boundary.** A strict v2 parser can be tested with in-memory fixtures without importing a v2 file or changing the fixed unavailable v1 runtime path. This preserves a useful implementation seam without converting a candidate, report, sample, or ignored local export into Official data.
46. **2026-07-13 — Selection state needs one discriminated value, not synchronized flags.** Derive the provider input and visible mode from one selection result and test the exact React tree with a parser-produced fixture; then an unavailable request can demonstrably retain both the Demo label and Demo values.
47. **2026-07-13 — Broad inherited context can stall a bounded internal review.** Fork only the focused task context (or keep the audit prompt exceptionally small), use a short watchdog, record the absence of telemetry, and retain parent-owned executable checks as the acceptance path.
48. **2026-07-13 — Do not mark an operable explanation control as disabled.** If a data-source button remains keyboard-operable so it can explain an unavailable state, `aria-disabled` is contradictory; pair an explicit label and `aria-describedby` with the live status instead.
49. **2026-07-13 — Test actual focus, not just click handlers.** Programmatic `.click()` does not establish browser focus. Focus the control before the interaction and assert the post-commit active element when validating a mode transition.
50. **2026-07-13 — Component fixtures must distinguish semantic controls.** A generic checkbox selector can target a filter Switch rather than a table-row selection; select by its table relationship or accessible role/name to prove the intended reset behavior.
51. **2026-07-14 — Treat public static delivery, private ingestion compute, the database, and artifact storage as separate architecture decisions.** A Pages/Vercel choice does not make the ledger runnable or a release approved; begin with a digest-pinned static artifact and add a public API only after a concrete use case and threat model justify it.
52. **2026-07-14 — Fail closed at the real network boundary, and label unavailable evidence honestly.** DNS preflight alone cannot prove the peer an HTTP client reaches after resolution; keep live transport disabled until an approved private runner can enforce peer-pinning and egress policy. Likewise, JSDOM/component checks do not substitute for a browser or assistive-technology matrix—record the unavailable browser receipt rather than promoting a local test into launch proof.
53. **2026-07-15 — A user platform choice narrows architecture, not authority.** Recording Cloudflare Pages as the static-host preference does not name an operator or authorize account creation, DNS, Workers, storage, deployment, or a public data API. Preserve the static-artifact boundary until those separate decisions and release gates exist.
54. **2026-07-15 — Registry activity is not evidence readiness, and the field name matters.** The executable registry uses a status value, not an active boolean. Count and admission checks must inspect the authoritative field and policy together; an active route can still be intentionally fail-closed. Build breadth through individually certified direct artifacts, never by reviving routes or treating a preview endpoint as a complete result source.

55. **2026-07-15 — Make certification order evidence-led and enforce it before fetch.** A compact complete artifact can be technically preferable to a familiar endpoint, but neither technical convenience nor a task-data license proves result-data reuse. Bind exact locators and lexical values to a reviewed source revision, reject preview and terms-blocked URLs before an adapter runs, and keep generic fixtures separate from source authorization.
56. **2026-07-15 — Broad automation plans need a cross-boundary confirmation cycle.** A credible “run twice daily and alert us” design is not complete at Cron/Queue: it must connect proposal → certification → atomic cutover, durable slot → fenced attempt → snapshot-before-extraction, typed system identity → public artifact identity, and primary outbox → failure-independent watchdog/recovery. The specialist adversarial pass exposed these seams after the first synthesis; require the same lanes to confirm their fixes before handing future production plans to implementation.
57. **2026-07-15 — Persist semantic invariants, then run the expensive suite.** JSON Schema comments and ephemeral probes do not enforce cross-field lifecycle, authority, digest, duplicate-ID, or URL-policy rules. Put those rules in executable validators with adversarial fixtures, reserve an independent review before the long full-suite run, and use parent integration plus actual CLI/no-write evidence—not a worker DoneClaim—as acceptance authority.
58. **2026-07-15 — Review exact composition denominators, not only terminal references.** A final receipt can bind one correct terminal object while silently omitting or substituting subordinate attempt, snapshot, or incident facts. Derive child identities from the parent attempt, reconcile complete sets without row-order selection, and make blocked admission paths produce an honest attempt-shaped receipt.
59. **2026-07-15 — Names and happy-path grants are not executable persistence proof.** Bind admitted bytes to factory-only receipt identities, inspect exact schema state (owners, defaults, triggers, functions, index definitions and validity, persistence, RLS, and inheritance), and declaratively converge role attributes, ownership, memberships, and grants. Before the expensive suite, adversarially poison each dimension and require the target to fail closed.

60. **2026-07-15 — Constraint catalog rows are not executable FK proof, and payload time is not commit time.** Strict PostgreSQL status must verify every reviewed FK's internal RI triggers and normal enabled state. Lease acceptance must sample a trusted application clock and independently enforce database time at insertion/commit, so disabled enforcement or backdated payloads cannot masquerade as current work.
61. **2026-07-15 — Pre-dispatch intent, terminal evidence, and external authority are three different facts.** Persist honest intent before work, atomically compose mutually referring immutable attempt/receipt evidence with reviewed deferral, and append terminal denominators only when complete. None of those mechanics starts a scheduler, certifies a source, sends an alert, or authorizes a provider.

62. **2026-07-16 — Fresh-target recovery is a cross-resource admission problem.** Prove database-scoped state as well as schema rows, resolve evidence outputs outside every immutable input root, and consume a new target before restore. Re-run the repaired boundaries on distinct real targets, then require a different stable-hash reviewer before spending the full-suite gate.
