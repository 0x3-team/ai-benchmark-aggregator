## Purpose

This checkpoint starts the model-list work before any synthetic-data cutover. It
captures a bounded, source-hashed candidate inventory and makes the next owner
responsible for identity reconciliation. The inventory is not an Official
artifact, does not certify a source, and must not be imported into the runtime
catalog or claims ledger without review.

is only a lead. It does not merge versions, providers, aliases, benchmark
systems, embeddings, adapters, or unrelated ML models.

## Required next owner actions

1. Define the comparison scope: chat/reasoning, coding, multimodal, embedding,
   reranking, image/audio, benchmark systems, and test fixtures.
2. Review every candidate disposition: `confirmed`, `needs_review`,
   `deprecated`, `non_comparison_model`, or `synthetic_fixture`.
3. Build canonical identities with provider IDs, API IDs, Hugging Face IDs,
   OpenRouter IDs, aliases, version relationships, and evidence references.
4. Enrich confirmed identities with vendor, family, release date, context,
   parameters, modalities, weights, pricing, official URLs, and status.
5. Produce a reviewed model catalog and an append-only decision receipt.
6. Only after that receipt is accepted, remove synthetic runtime scores and
   switch the UI to the unavailable Official state.
